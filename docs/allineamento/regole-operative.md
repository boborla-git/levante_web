# Regole operative progetto

## Regole obbligatorie

1. Prima di ogni modifica verificare GitHub in tempo reale e confermare la baseline.
2. Non usare memoria, ZIP o file caricati come fonte ufficiale se GitHub e' disponibile.
3. Consegnare solo file completi, con lo stesso nome e percorso del repository.
4. Indicare sempre il commit summary da usare in GitHub Desktop.
5. Non modificare file non necessari e non introdurre refactoring non richiesti.
6. Prima di toccare CSS, layout, permessi, notifiche o email, dichiarare i contratti impattati.
7. Non rimuovere JavaScript locale o logiche applicative se implementano comportamenti gia' approvati.
8. L'utente non crea file e non modifica il database autonomamente: carica solo i file preparati e/o esegue SQL forniti esplicitamente.
9. Admin deve rimanere super-user globale.
10. Il template email HR approvato e' golden master e non deve essere degradato.

## Metodo consegna

Ogni consegna deve includere:

- elenco file completi da caricare;
- cosa cambia;
- cosa non cambia;
- controlli regressione consigliati;
- commit summary.
